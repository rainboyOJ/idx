# Rainboy 导航 UI/UX 精修 V2 实施规范

> 状态：已确认，供实施 AI 直接执行
>
> 确认日期：2026-08-17
>
> 设计方向：精密控制台（Precision Console）
>
> 实施范围：只重做视觉层级、组件表面、响应式密度和细节状态，不改变产品数据与核心行为

## 1. 文档权限与实施原则

本文档是现有 `docs/ui-ux-redesign.md` 的视觉精修补充，而不是功能重写。

- 本文档优先决定配色、字体、间距、卡片、分类索引、工作栏、动效和视觉状态。
- 原文档继续决定数据完整性、搜索语义、键盘行为、可访问性、构建流程、性能预算和浏览器范围。
- 如两份文档在纯视觉细节上冲突，以本文档为准；如涉及数据或行为，以原文档和现有测试为准。
- 实施前先阅读当前 `git diff`，保留工作区已有修改；不得使用 `git reset --hard`、`git checkout --` 等命令覆盖用户工作。
- `index.pug` 是页面结构源文件，`index.html` 只能通过 `./build.sh` 生成，不得直接手改。
- 不执行 `push.sh`，不部署，不自动提交。

## 2. Design Brief

### 2.1 当前问题

现有页面功能完整，但视觉权重过于平均：119 个网址条目使用相近的白色卡片、边框和外链图标，分类区块之间缺少足够节奏，长页面容易呈现为连续的卡片墙。荧光色在大量外链图标上重复出现，也削弱了真正重要状态的辨识度。

### 2.2 目标体验

页面应像一个长期使用的个人精密控制台：

- 第一眼识别为个人网址导航，搜索是最明确的主操作。
- 保持高信息密度，但通过编号、对齐、字号、明度和留白建立层级。
- 科技感来自结构与信息编码，而不是霓虹、纹理或装饰。
- 桌面端优先支持快速扫描；移动端完整可用且不过度占用首屏。
- 浅色和深色主题具有同一视觉性格，不使用简单颜色反相。

### 2.3 核心用户与任务

主用户是熟悉这些网址的个人用户。核心任务仍是：进入页面，通过搜索或分类快速找到一个已知网址，然后打开它。任何视觉元素都不得延长这条路径。

### 2.4 成功标准

- 搜索框、当前分类和网址标题形成清晰的三级视觉优先级。
- 1440px 首屏可以快速区分工作栏、分类索引、分区标题和网址条目。
- 119 个条目同时存在时仍有明确区块节奏，不形成连续白盒噪声。
- 浅色与深色主题均达到 WCAG 2.2 AA 对比要求。
- 现有搜索、键盘、主题、图标回退和 scrollspy 行为不退化。

### 2.5 明确不做

- 不新增收藏、最近访问、登录、同步、推荐、联网搜索或后端。
- 不新增 Hero、营销文案、功能介绍区、快捷键装饰标签或引导卡片。
- 不分页、不折叠分类、不使用瀑布流，不改变 `config.yaml` 顺序。
- 不引入远程字体、远程 UI 资源或新的前端框架。

## 3. Information Architecture

页面保持四层结构：

1. **Workbar**：品牌、搜索、结果数量、主题切换。
2. **Category Index**：桌面左侧索引；平板和手机为横向分类栏。
3. **Directory**：按原顺序排列的分类标题与网址条目网格。
4. **Utility**：返回顶部、搜索空状态、页脚和无障碍跳转链接。

必须保持：

- 11 个分类、119 个网址及其名称、描述、URL、归属和顺序不变。
- `config.yaml` 仍是唯一内容数据源。
- 全部网址仍安全地在新标签页打开。
- 页面可通过 `file://` 直接使用，不增加运行时数据请求。

## 5. Visual Design

### 5.1 视觉原则

- **精确**：使用两位分类编号、等宽元数据、固定尺寸和严格对齐。
- **安静**：大面积使用冷中性色，高饱和色只用于状态。
- **分层**：通过三个表面明度、排版和间距建立层级，减少边框依赖。
- **直接**：整张网址条目可点击，搜索反馈即时，不增加中间步骤。
- **克制**：不使用视觉噱头，不让动效或装饰与内容争夺注意力。

建议颜色占比：中性色约 85%，钴蓝约 12%，荧光黄不超过 3%。

颜色使用规则：

- 外链图标默认使用次级或三级文字色，悬停和聚焦时变为钴蓝。
- 禁止让所有外链图标默认显示荧光黄。
- `--color-border` 只用于非必要的视觉分隔；输入框、焦点邻接边界等必要 UI 边界使用 `--color-border-strong`。
- 正常文字对背景对比度至少 4.5:1；UI 边界与焦点至少 3:1。若实测不达标，只允许向更高对比度微调，不改变已确认的色相方向。

### 5.3 字体与排版

不加载远程字体。使用以下两套系统字体：

```css
  "PingFang SC", "Microsoft YaHei", sans-serif;

  "Liberation Mono", monospace;
```

| 内容 | 字号 / 行高 | 字重 | 字体 |
| --- | --- | --- | --- |
| 品牌名称 | 18px / 24px | 700 | 无衬线 |
| 分类标题 | 16px / 22px | 650 | 无衬线 |

- `01`、`119 LINKS`、域名和计数使用等宽字体。
- 中文标题不使用等宽字体。
- 所有文字 `letter-spacing: 0`，禁止负字距。
- 字号不随视口宽度缩放，不使用 `vw` 或 `clamp()` 控制字体。

## 6. Component Specifications

### 6.1 Workbar

桌面端为固定 64px 单行工作栏：

```text
[R] Rainboy 导航   [搜索输入........................ ×]   119 LINKS   [主题]
```

- 工作栏使用实色表面和底部 1px 分隔线，无模糊、透明或阴影。
- 品牌区域宽度与 208px 分类栏对齐。
- `R` 标识为 32 × 32px 钴蓝方块，圆角不超过 6px。
- 搜索框高度 44px，最大宽度约 640px，优先获得弹性空间。
- 结果数量使用等宽文字；默认 `119 LINKS`，搜索时为 `10 / 119`。
- 主题切换为 44 × 44px 图标按钮，使用 Lucide 太阳/月亮图标。

移动端工作栏为两行：

- 第一行 56px：品牌在左，结果数量和主题按钮在右。
- 第二行 56px：搜索框占满可用宽度。
- 搜索输入字号至少 16px，防止 iOS 聚焦自动缩放。
- 工作栏下方紧接 48px 分类栏，移动端黏性区域总高约 160px。

### 6.2 SearchField

| 状态 | 视觉与行为 |
| --- | --- |
| 默认 | 中性边框、次级搜索图标、显示总数 |
| 悬停 | 边框提高一个对比层级 |
| 聚焦 | 钴蓝边框与 2px 外部焦点环，尺寸不变 |
| 有值 | 显示固定 44px 点击区域的清空按钮 |
| 有结果 | 数量同步更新，匹配片段使用荧光黄 |
| 零结果 | 数量为 `0 / 119`，分类导航隐藏，空状态显示 |

- 保留可访问的 `<label>`，可视觉隐藏但不得只依赖 placeholder。
- 搜索、清空和筛选必须即时完成，不显示加载动画。
- 不新增联想、历史搜索、远程请求或快捷键可视徽章。
- 超长查询必须换行或截断在自己的容器内，不得扩展页面宽度。

### 6.3 CategoryIndex（桌面）

```text
INDEX / 11

01  网站                         26
02  题单                         15
03  团队                          3
```

- 宽度 208px，不使用独立卡片或外层圆角容器。
- 标题 `INDEX / 11` 使用 12px 等宽字体。
- 每项最小高度 44px，分类编号、名称、数量严格对齐。
- 两位编号由分类在 `config.yaml` 中的一基序号派生，不写回配置文件。
- 移除分类 Lucide 图标，以编号作为统一视觉标识，避免编号与图标重复。
- 默认项不使用胶囊底色；当前项显示左侧 2px 钴蓝指示线、浅蓝表面和高对比文字。
- 数量使用等宽数字并右对齐。

CategoryIndex 是页内锚点导航，不是 Tab 组件。不得添加 `role="tablist"`、`role="tab"` 或 Tab Panel 语义。

### 6.4 CategoryRail（平板与移动）

- 总高度 48px，分类链接可点击高度至少 44px。
- 单行横向滚动，显示 `01 网站 26`，省略分类图标。
- 当前项使用底部 2px 钴蓝线和高对比文字，不使用大面积蓝色胶囊。
- 保留左右渐隐溢出提示和活动项自动滚入可见区域。
- 渐隐只表示可滚动，不改变点击尺寸、布局或 Tab 顺序。
- 滚动定位必须使用绝对目标位置并包含当前 `scrollLeft`。

### 6.5 SectionHeading

```text
01 / 网站                                      26 LINKS
────────────────────────────────────────────────────────
```

- 编号使用钴蓝等宽字体；中文名称使用 16px 半粗体。
- 数量为 12px 等宽文本，不使用徽章或胶囊。
- 标题下方分隔线贯穿当前内容区域。
- 标题与首行卡片间距 12px；分类区块之间桌面 32px、移动 24px。
- 分类标题不设为 sticky，避免与顶部工作栏和分类栏形成多重黏性层。

### 6.6 LinkCard

```text
┌─────────────────────────────────┐
│ [图标]  Rbook                 ↗ │
│         全新的感觉              │
│         rbook.roj.ac.cn          │
└─────────────────────────────────┘
```

- 整张卡片仍是一个原生链接，桌面高 76px，移动高 72px。
- 图标承载框为 36 × 36px，网站图标在其中以 26–28px 显示。
- 内容顺序固定为标题、描述（存在时）、域名。
- 标题、描述和域名按第 5.3 节排版；均保持稳定截断，不撑高卡片。
- 默认使用主题独立的半透明 `--color-card-glass` 表面、内侧明暗边缘和克制的 3px / 10px 外阴影。
- `::before` 组合径向高光与低强度线性色彩折射；这是 LinkCard 专用的液态玻璃材质，不扩展到页面区块、工作栏或侧栏。
- 深色模式降低白色高光并增加蓝色折射，使玻璃边缘清晰但不压低文字对比度。
- 精细指针悬停或键盘聚焦时，当前卡片才启用 14px 背景模糊与 135% 饱和度；避免 119 张卡片同时创建昂贵的模糊层。
- 精细指针悬停时还使用 `--color-card-glass-hover`、钴蓝边框、`perspective(700px)`、`translateY(-3px)` 和 `scale(1.01)`。
- 卡片根据指针相对中心的位置动态设置 `rotateX` / `rotateY`，中心接近 0deg。考虑到卡片宽高比，纵向移动使用 `rotateX` 最大 ±9deg，横向移动使用 `rotateY` 最大 ±5deg；指针离开后平滑复位。
- 同一指针坐标映射到 `--glass-x` / `--glass-y`，让高光反射与倾斜方向同步；离开时四个动态变量一起清理。
- 触摸设备不启用 3D 倾斜和跟随高光，但保留静态玻璃材质、普通按压和颜色反馈。
- 激活时回到原位；键盘聚焦显示完整 2px 焦点环。
- 外链图标占用固定 16px 区域，默认灰色；悬停和聚焦时变为钴蓝并向右上移动 1px。
- 外链图标在触控设备上保持可见但低对比，不依赖 hover 才表达链接语义。
- 搜索命中只高亮匹配文字，不改变卡片高度、字号或排列。

### 6.7 网站图标与回退

- 网站自身图标保留原色，不施加统一滤镜。
- 全部图片设置固定宽高，继续懒加载非首屏图标。
- 加载失败或配置缺失时，显示相同尺寸的首字符回退。
- 回退使用钴蓝或中性表面，并保证字符对比度，不引发布局偏移。
- 图标错误不使用 Toast、弹窗或占据卡片说明区域。

### 6.8 EmptyState

- 不使用外层卡片。
- 使用 32px 搜索图标、18px 标题、当前查询词和“清空搜索”按钮。
- 查询词使用次级色并允许 `overflow-wrap: anywhere`。
- “清空搜索”使用 X 图标与文字，点击后恢复全部网址并将焦点留在搜索框。
- 零结果不是系统错误，不使用红色警告样式。

### 6.9 ThemeToggle

- 44 × 44px 纯图标按钮，使用 Lucide 太阳/月亮图标。
- 浅色和深色图标通过淡入淡出切换，不做大角度旋转。
- 具有随当前状态变化的可访问名称，例如“切换到深色主题”。
- 继续优先使用已保存主题；存储不可用时跟随系统主题并保持按钮可操作。

### 6.10 BackToTop

- 44 × 44px 向上箭头图标按钮，滚动超过约 640px 后显示。
- 固定于右下角；桌面距边缘 24px，移动距边缘 16px，并考虑 `env(safe-area-inset-bottom)`。
- 使用实色表面、结构边框和明确焦点环，不使用文本胶囊。
- 减少动画模式下立即返回顶部。
- 不得遮挡卡片、页脚或其他控件。

### 6.11 Footer

- 保持单行、低权重、无卡片背景。
- 使用 12px 次级文字，不成为首屏视觉信号。
- 不新增说明性文案、社交链接或额外导航。

## 7. Responsive Design

只使用现有三个主断点：720px、1024px、1440px。不得为局部微调随意增加断点。

| 范围 | 页面边距 | 分类导航 | 卡片网格 | 主要尺寸 |
| --- | --- | --- | --- | --- |
| 320–719px | 16px | 48px 横向栏 | 1 列，8px 间距 | 卡片 72px；顶部黏性总高约 160px |
| 720–1023px | 20px | 48px 横向栏 | 2 列，12px 间距 | 工作栏仍为移动两行结构 |
| 1024–1439px | 24px | 208px 左侧栏 | 3–4 列，12px 间距 | 工作栏 64px 单行 |
| ≥ 1440px | 32px | 208px 左侧栏 | 4 列；空间足够时 5 列 | 全部内容最大宽度 1680px |

桌面布局要求：

- 内容区整体最大宽度 1680px 并水平居中。
- 左侧栏与主目录之间为 24px 间距。
- 卡片网格使用 `auto-fill` 和 232px 的最小轨道，避免少量卡片拉满整行；该宽度保证 1024px 布局仍能容纳 3 列，并使 1920px 布局最多容纳 5 列。
- 1440px 目标为稳定 4 列，1920px 目标为最多 5 列。
- 不使用瀑布流，DOM 顺序与视觉顺序一致。

所有宽度要求：

- 最窄支持 320px，无页面级横向滚动。
- 200% 浏览器缩放时文字不重叠、不被裁切，操作仍可完成。
- 字号不随断点变化；响应式只调整布局、间距和可见元数据位置。
- 触控目标至少 44 × 44px，相邻目标保持足够间距。

## 8. Interaction and Motion

### 8.1 保留行为

- `/` 与 `Ctrl+K` 在非可编辑区域聚焦搜索框。
- `Esc` 先清空搜索；搜索为空时再移出焦点。
- 搜索框内 `ArrowDown` 聚焦第一个可见网址。
- `Enter` 不在搜索框中擅自打开第一个结果。
- IME 组合输入期间不筛选，提交后更新一次。
- 首个非空查询只滚动一次到目录顶部；后续输入不重复滚动。
- 分类点击与 scrollspy 的 `aria-current` 保持一致。
- 清空搜索后恢复全部分类和 119 个网址，不强制回到页面顶部。

### 8.2 动效规格

```css
--motion: 180ms cubic-bezier(.2,0,0,1);
```

- 只允许对 `transform`、`opacity`、颜色和边框色做短过渡。
- 卡片 3D 悬停只在 `(hover: hover) and (pointer: fine)` 下启用，使用 `perspective(700px) translateY(-3px) scale(1.01) rotateX(...) rotateY(...)`。
- 指针位置由 `.directory` 上的委托事件读取，并通过 `requestAnimationFrame` 合并更新倾斜与玻璃高光坐标；每张卡片不单独绑定监听器。
- `prefers-reduced-motion: reduce` 下取消卡片倾斜、缩放和位移，并清理已设置的倾斜变量。
- 外链箭头最多 `translate(1px, -1px)`。
- 主题图标淡入淡出；返回顶部按钮使用轻微透明度和位移。
- 禁止首屏入场动画、119 张卡片依次出现、扫描线、闪烁、呼吸光、视差和循环动画。
- `prefers-reduced-motion: reduce` 下关闭平滑滚动、位移和非必要过渡。

交互状态不得改变元素占位尺寸或引发布局跳动。

## 9. Accessibility Requirements

目标为 WCAG 2.2 AA：

- 正常文字对比度至少 4.5:1；大文字和 UI 图形至少 3:1。
- 不能只用颜色表达当前分类：同时使用指示线、`aria-current` 和文字对比。
- 全部操作使用原生 `<a>`、`<button>`、`<input>` 等语义元素。
- 保留唯一 `h1`、顺序正确的 `h2` 分类标题、`main`、`nav`、`header` 和 `footer`。
- 保留跳到主要内容的 skip link，并确保其聚焦时可见。
- 所有图标按钮具有可访问名称；装饰图标对辅助技术隐藏。
- 搜索结果使用 `aria-live="polite"` 完整播报，例如“找到 10 个网址，共 119 个”和“显示全部 119 个网址”。
- 焦点环至少 2px、对比度至少 3:1，不能被 sticky 区域或 `overflow` 裁切。
- Tab 顺序与 DOM/视觉顺序一致，不使用正数 `tabindex`。
- 搜索过滤后隐藏项必须同时离开视觉、可访问性树和 Tab 顺序。
- 支持 `prefers-contrast`、`forced-colors` 和 `prefers-reduced-motion`。
- 页面允许浏览器缩放，不禁用 pinch zoom。

## 10. Implementation Guidelines

### 10.1 文件职责

| 文件 | 允许修改 | 约束 |
| --- | --- | --- |
| `config.yaml` | 原则上不改 | 不加入展示编号，不改变网址数据或顺序 |
| `index.pug` | 调整 Workbar、分类索引、分区标题和组件结构 | 保持语义；编号从循环索引派生 |
| `styles.css` | 重构 token、布局与组件视觉 | 替换旧规则，不在文件末尾叠加第二套主题 |
| `app.js` | 仅调整显示格式和必要状态协作 | 不重写已通过测试的搜索、键盘、主题和 scrollspy 核心逻辑 |
| `scripts/build.mjs` | 仅在模板数据确有需要时调整 | 不把视觉文案或编号写回 `config.yaml` |
| `index.html` | 仅由构建生成 | 禁止直接编辑 |
| `tests/*.mjs` | 更新结构断言并补充 V2 回归 | 不降低既有断言，不让普通测试覆盖视觉基准 |
| `tests/baseline/*.png` | 视觉确认后显式更新 | 先人工检查截图，再运行更新命令 |

### 10.2 实施顺序

1. 阅读本规范、原设计文档、现有测试和当前工作区差异。
2. 保存改造前桌面/手机浅色与深色截图，作为人工对照。
3. 先替换语义 token、字体和基础尺寸，不修改交互逻辑。
4. 调整 Workbar、CategoryIndex、CategoryRail 和 SectionHeading 结构。
5. 重做 LinkCard、EmptyState、ThemeToggle 和 BackToTop 状态。
6. 实现 720/1024/1440px 响应式布局与 200% 缩放适配。
7. 更新结构测试；运行全量测试、axe、Lighthouse 和构建检查。
8. 人工检查 8 张新截图后，才显式更新视觉基准。
9. 再运行普通视觉测试，确认它只比较、不改写基准。

### 10.3 禁止实现方式

- 不把新 CSS 简单追加在旧 CSS 末尾并依赖更高优先级覆盖。
- 不使用 `!important` 作为常规布局手段。
- 不通过删除测试、增加容差、隐藏内容或降低阈值制造“通过”。
- 除 LinkCard 液态玻璃所需的受控径向/线性高光、背景模糊和浅阴影外，不在其他组件加入渐变、背景纹理、点阵、发光、玻璃模糊、默认阴影或装饰性大标题。
- 不使用大于 8px 的卡片圆角，不嵌套卡片，不把页面区块包成浮动卡片。
- 不让荧光黄成为大面积品牌色或所有外链图标的默认颜色。
- 不新增包依赖，除非现有技术栈无法实现且用户另行批准。
