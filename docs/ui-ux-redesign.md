# Rainboy 导航 UI/UX 优化设计

> 状态：最终确认，可交付实施。本文档是交给实施 AI 的唯一 UI/UX 事实来源；实施中的任何偏差必须另行确认。

## 1. Design Brief

### 1.1 项目定位

Rainboy 导航是个人高频工作入口，不是公共网址目录或产品落地页。页面包含 11 个分类和 119 个网址，核心设计问题是如何降低高密度内容中的定位与扫描成本。

### 1.2 主用户

主用户是熟悉现有分类、网址名称和大致位置的 Rainboy 本人。

### 1.3 已确认的设计优先级

1. 快速定位常用网址。
2. 保持熟悉内容的位置与结构稳定。
3. 在可扫描的信息密度和视觉舒适度之间取得平衡。
4. 形成适合长期使用、不过度装饰的视觉风格。
5. 品牌展示和陌生用户引导不作为首要目标。

### 1.3.1 成功指标

使用 10 个分布在不同分类的代表性目标网址进行人工任务测试：

- 桌面端通过网址搜索定位并打开目标网址的中位时间不超过 5 秒。
- 桌面端通过分类定位并打开目标网址的中位时间不超过 8 秒。
- 390px 移动端定位并打开目标网址的中位时间不超过 10 秒。
- 10 次任务中不发生误点或找不到目标网址。
- 5 秒第一印象测试后，测试者能够回答“这是个人网址导航，主要操作是搜索或按分类打开网站”。

### 1.4 核心用户旅程

1. 主用户进入导航页。
2. 主用户凭名称、图标或所属分类定位目标网址。
3. 主用户打开目标网址并离开导航页。

核心任务是打开一个已经知道的目标网址，而不是浏览推荐内容或发现新网址。新增功能与视觉元素必须优先缩短这条路径，不能以展示性内容干扰它。

### 1.5 设备优先级

- **桌面端是主场景**：优先支持鼠标和键盘操作，保持较高信息密度，使主用户能快速扫描大量网址。
- **移动端是完整可用的次要场景**：保留全部核心能力，提供至少 44 × 44 CSS px 的触控目标和适合窄屏的内容层级，但不要求复制桌面端的信息密度。

### 1.6 功能范围

本次优化允许新增“网址搜索”。搜索只在浏览器中对当前页面已有网址条目进行过滤，不接入后端或互联网搜索。视觉改造和搜索共同服务于快速打开目标网址的核心任务。

明确不在本次范围内：收藏、置顶、最近访问、访问频率排序、拖拽排序、页面内编辑、登录、跨设备同步和互联网搜索。这些能力不得以“顺手优化”为由加入。

### 1.7 搜索入口与基本行为

- 在页面标题区域提供桌面端和移动端始终可见的紧凑搜索框。
- `/` 和 `Ctrl+K` 聚焦搜索框；当焦点位于可编辑控件中时，不拦截这些按键。
- `Esc` 清空查询；再次按下时将焦点移出搜索框。
- 输入查询后，在当前位置过滤网址卡片；没有匹配项的分类同时隐藏。
- 搜索结果区域显示匹配网址数量，并通过礼貌型 live region 向屏幕阅读器报告。
- 搜索不使用模态框，不跳转新页面，不改变网址数据。
- 当搜索框有焦点且存在匹配项时，`ArrowDown` 将焦点移动到第一个可见网址条目。
- 进入网址条目后使用原生 `Tab` / `Shift+Tab` 顺序导航和 `Enter` 打开；不得实现 ARIA Grid、roving tabindex 或自定义方向键网格导航。
- 搜索框中的 `Enter` 不自动打开第一个结果。
- 当查询从空字符串首次变为非空时，自动滚动一次到网址目录顶部；同一轮查询的后续输入不得继续改变滚动位置。
- 清空搜索不强制滚动到页面顶部。自动滚动遵守 `prefers-reduced-motion`，减少动画模式下使用即时定位。
- 搜索查询是一次性页面状态，不写入 URL、`localStorage`、`sessionStorage` 或浏览器历史；刷新后恢复完整目录。
- 只有主题偏好继续持久化。
- 页面加载后不自动聚焦搜索框，避免移动端弹出软键盘并保留浏览器正常起始焦点。
- 119 个网址的数据量允许在每次有效 `input` 事件后立即过滤，不添加 debounce；输入法组合期间检查 `event.isComposing`，避免在中文尚未完成时更新结果。

### 1.8 搜索匹配规则

- 搜索索引包含网址标题、描述、域名和所属分类。
- 查询与索引统一执行 Unicode NFKC 规范化、去除首尾空格并转换为小写，从而忽略大小写和全角/半角差异。
- 使用可预测的包含匹配。
- 首版不实现拼音匹配、编辑距离纠错、模糊搜索或外部搜索库。
- 过滤结果继续保持 `config.yaml` 中的分类顺序和分类内网址顺序，不采用相关度排序。
- 在可见的网址标题、描述和域名中使用 `<mark>` 高亮实际命中片段；分类字段命中只参与过滤，不高亮整张条目。
- 高亮使用荧光黄背景与深色前景，并在两套主题中满足文字对比度。
- 高亮实现必须创建文本节点和 `<mark>` 元素，不得把用户查询插入 `innerHTML`。
- 若 NFKC 规范化后的命中位置无法安全映射回原始字符串，保留匹配结果但不高亮该字段。
- 搜索期间，分类导航数量和分类标题数量都显示当前匹配数；清空查询后恢复 `config.yaml` 中的原始数量。
- 规范化后按连续空白切分为多个非空关键词，并使用 AND 语义：每个关键词可命中任意搜索字段，但所有关键词都必须在该网址条目的联合索引中出现。
- 仅包含空白的查询等同于空查询，恢复完整目录。

### 1.9 搜索空状态

- 零匹配时，在网址目录原位显示紧凑空状态，包含 `lucide:search`、标题“没有匹配的网址”、当前查询词和“清空搜索”按钮。
- “清空搜索”必须是原生按钮，激活后清空输入、恢复全部分类与网址，并把焦点返回搜索框。
- 零结果时暂时隐藏分类导航，避免显示无法跳转的分类。
- 不显示插画、推荐网址，不提供互联网搜索或自动改写查询。

## 2. Information Architecture

### 2.1 内容结构约束

- 保持当前 11 个分类、119 个网址及其顺序。
- 不修改分类名称，不合并“资料 / 资源”等近义分类，不修正“AIa”等现有名称。
- 不移动网址所属分类，不删除或新增网址。
- 分类内容审计属于独立任务，不得混入本次 UI/UX 实施。

### 2.2 页面层级

1. 粘性工作栏：品牌标识、站点名称、网址搜索、数量摘要和主题切换。
2. 分类导航：稳定呈现全部分类及数量。
3. 网址目录：按既定分类顺序展示网址条目。
4. 页尾：数据更新时间。

### 2.3 粘性工作栏

- 删除当前页头下方重复的大标题区。
- 桌面端使用稳定高度的单行工作栏：品牌在左、搜索居中并占主要弹性空间、数量摘要与主题切换在右。
- 移动端使用两行工作栏：第一行放品牌与主题切换，第二行放全宽搜索和紧凑匹配数量。
- 工作栏在页面滚动时保持顶部粘性；高度、图标和计数变化不得引发布局跳动。
- 工作栏使用实色或近乎不透明的承载面与清晰底边，不使用玻璃模糊。
- 工作栏不显示 `site.description` 副标题；该值继续保留在 `config.yaml` 和页面元数据中。
- “Rainboy 导航”承担页面唯一 `h1`，与 `R` 标识共同形成品牌区。
- 未搜索时数量摘要显示“119 个网址”；搜索时在同一稳定宽度区域显示“匹配数 / 119”。
- 数量摘要只显示网址数，不同时显示分类数；可视数字使用等宽字体。
- 屏幕阅读器状态文本使用完整句子，例如“找到 12 个网址，共 119 个”。

### 2.4 分类导航

- 桌面断点及以上使用约 208px 宽的粘性左侧分类栏，一次显示全部 11 个分类及数量。
- 左侧分类栏与网址目录属于同一内容布局，不把侧栏包进独立装饰卡片。
- 小于桌面断点时，分类导航转换为工作栏下方的单行横向标签栏。
- 横向标签栏允许触控和触控板滚动，隐藏原生滚动条，但必须通过边缘渐隐提示溢出方向。
- 当前活动分类使用颜色、形状或边框等至少两种线索表达，不能只依赖颜色。
- 滚动页面或点击分类后，活动分类标签自动滚入可视区域；应尊重 `prefers-reduced-motion`。
- 分类数量使用右对齐的等宽纯数字，不使用填充胶囊或圆形徽章；活动状态可以改变数字颜色或边界，但不能改变其占用宽度。
- 正常浏览时，通过 `IntersectionObserver` 根据最接近粘性顶部区域的可见分类更新 `aria-current="true"`。
- 搜索期间只观察仍可见的分类；零结果时清除活动分类。
- 点击分类跳转时，为分类区块设置与工作栏实际高度一致的 `scroll-margin-top`，分类标题不得被遮挡。
- 移动端活动分类变化后，将对应标签滚入可视区域；自动移动遵守 `prefers-reduced-motion`。

### 2.5 网址条目内容层级

- 网址条目是高频工具组件，不是展示型内容卡片。
- 桌面端高度控制在 76–84px，移动端单列且高度不低于 80px；整个条目均为可点击区域。
- 圆角使用 6px，不使用胶囊形或大圆角。
- 图标视觉框尺寸为 38–40px，不能因加载、悬停或回退文字改变布局。
- 第一层为网址标题，单行截断；第二层为描述或域名，单行截断；当描述存在且不同于域名时，第三层显示域名并使用最弱层级。
- 文字过长时使用省略号，并通过原生 `title` 或可访问描述提供完整内容；不得增加条目高度。
- 移动端触控目标至少 44 × 44 CSS px，条目之间至少保留 8px 间距。
- 所有网址继续使用 `target="_blank"` 和 `rel="noopener noreferrer"` 在新标签页打开；条目保留外链图标和屏幕阅读器说明。
- 移动端继续显示标题、描述和必要时的域名三层信息；每层保持单行截断，不通过隐藏域名缩短条目。

### 2.6 响应式网址网格

- 以移动端单列为默认布局。
- 平板宽度使用 2 列；进入桌面布局后，根据可用内容宽度自动形成 3–4 列；超宽桌面最多 5 列。
- 使用约 240px 的最小网格轨道宽度和 `auto-fill`/`auto-fit`，但必须通过容器最大宽度阻止无限增列。
- 页面整体最大内容宽度约 1680px 并居中；在更宽屏幕上增加外侧留白，不拉伸条目高度或字号。
- 建议验证视口：320、390、768、1024、1366、1440、1920px。
- 不允许出现页面级水平滚动；只有窄屏分类标签栏可以有意横向滚动。

主要断点只使用以下三个：

| 断点 | 行为变化 |
| --- | --- |
| `720px` | 单列移动布局进入双列平板网格；工作栏仍保持窄屏结构 |
| `1024px` | 横向分类标签切换为约 208px 的粘性左侧栏；工作栏进入桌面单行结构 |
| `1440px` | 扩大外侧留白，并根据可用宽度允许第四或第五列 |

不得继续保留用途重叠的 `960px`、`1280px` 等旧断点。只有在组件自身发生真实布局断裂且上述断点无法覆盖时，才允许新增有书面理由的局部断点。

### 2.7 分类区块标题

- 分类区块本身不使用卡片背景、外层边框或悬浮面板。
- 标题行依次包含 Lucide 分类图标、18px 分类名称和等宽网址数量。
- 数量之后使用一条低对比 1px 分隔线填充剩余宽度，帮助划分长页面区块。
- 分类标题不设为粘性元素；页面方向由粘性分类导航表达，避免多个粘性层互相遮挡。
- 标题行尺寸固定，数量位数变化不得推动或缩放其他元素。

## 4. Visual Design

### 4.1 视觉性格

页面应呈现“安静、精确、略带技术感的个人学习工作台”：

- 高信息密度，但通过清晰层级和稳定间距保持从容。
- 以中性色承载主要内容，以少量高辨识度的科技主色和信号色表达选中、焦点和外链动作。
- 边界清晰，装饰克制，优先使用排版、间距和明度差建立层级。
- 不采用营销页构图、玻璃拟态、赛博霓虹、渐变光球、大面积插画或装饰性背景。
- 不把页面改造成松散的大卡片陈列；网址条目仍是紧凑、可重复扫描的工作组件。
- 页面背景保持纯色，不加入点阵、网格、噪点纹理、背景插画或装饰渐变；科技感由结构线、状态色、图标和排版建立。

### 4.2 主题策略

- 同时提供浅色与深色主题。
- 首次访问使用 `prefers-color-scheme` 跟随系统主题。
- 用户手动切换后，将选择保存在本地并在后续访问中优先使用。
- 两套主题共享相同的语义 token、组件层级和状态含义，分别校准明度与对比度，不使用颜色反相生成。
- 两套主题均须达到 WCAG 2.2 AA：普通文本至少 4.5:1，大文本和非文本 UI 至少 3:1。

### 4.3 色彩方向

- **基础色**：使用真正中性的石墨黑、冷白和灰阶建立背景、表面、文字与边界，不把中性色染成蓝色。
- **科技主色**：使用电光钴蓝表达品牌、活动分类、链接悬停、主要焦点和搜索状态。
- **信号色**：使用少量荧光黄表达外链方向、快捷状态或极少数高辨识提示；不得用于大面积背景或长段文字。
- 不使用青绿品牌色、紫色主导配色、蓝紫渐变、霓虹外发光或多色渐变。
- 浅色主题中的荧光黄若无法直接满足 3:1 非文本对比度，必须配合深色描边、深色承载面或改用通过对比度的深黄语义变体。

核心色值：

| 语义 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 页面背景 | `#F5F7FA` | `#0C0E13` |
| 条目表面 | `#FFFFFF` | `#141820` |
| 主文字 | `#141821` | `#F3F6FB` |

### 4.4 字体策略

- 不加载远程 Web Font，不新增大型中文字体文件。
- 主要文字使用系统 UI 无衬线字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 域名、计数和少量技术元信息使用系统等宽字体栈：`ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", monospace`。
- 中文标题、网址标题仍使用无衬线字体，不把整张卡片改成等宽字体。
- 所有文字 `letter-spacing: 0`；不使用负字距，也不按视口宽度连续缩放字号。

排版层级：

| 用途 | 字号 / 行高 | 字重 | 字体 |
| --- | --- | --- | --- |
| 页面/品牌标题 | 24px / 32px | 700 | 无衬线 |
| 分类标题 | 18px / 24px | 650（不支持时 600） | 无衬线 |
| 网址标题 | 14px / 20px | 650（不支持时 600） | 无衬线 |
| 正文、搜索输入 | 15px / 22px | 400–500 | 无衬线 |
| 描述 | 13px / 18px | 400 | 无衬线 |
| 域名、计数 | 12px / 16px | 400–500 | 等宽 |

移动端沿用同一字号，不通过 `vw`、`clamp()` 或媒体查询缩放文字；只调整布局、间距和可见信息层级。文本在 200% 缩放时仍须可读且不遮挡相邻内容。

### 4.5 间距系统

- 基础单位为 4px，只使用 `4 / 8 / 12 / 16 / 24 / 32 / 48px` 作为常规间距 token。
- 网址条目网格间距为 12px。
- 分类区块之间为 32px；分类标题与网址网格之间为 16px。
- 桌面页面水平边距为 32px，移动端为 16px；超宽屏由最大内容宽度产生额外外侧留白。
- 组件内部优先使用 8、12、16px，不引入零散的 10、14、18px 间距。

### 4.6 网址条目表面与状态

- 默认状态使用纯色表面、1px 低对比边框和零阴影。
- 悬停状态将边框切换为钴蓝，表面仅提高一个明度层级，并执行最多 `translateY(-1px)` 的位移。
- 按下状态取消位移并使用更深表面，提供直接反馈。
- 键盘焦点使用至少 2px、与相邻颜色达到 3:1 的外轮廓，轮廓不得被容器裁切。
- 不使用霓虹发光、3D 倾斜、弹跳或持续循环动画。
- 所有过渡限制在颜色、边框、背景和 `transform`，时长 120–180ms；减少动画模式下立即切换。

### 4.7 网址图标

- 保留现有网站图标，不统一替换为抽象线性图标。
- 所有网站图标放入固定 40 × 40px、6px 圆角的中性承载框；图片使用 `object-fit: contain`，四周保留稳定内边距。
- 不自动改变品牌图标颜色，不给图标施加整体彩色滤镜。
- 图标加载失败或配置缺失时，显示网址标题首字符；回退状态使用钴蓝底与满足 AA 对比度的前景色。
- 图片与回退文字必须占用相同尺寸，切换时不得造成布局偏移。

### 4.8 分类图标

- 重新设计全部 11 个分类图标；每个分类使用不同且语义明确的线性图标。
- 全部分类图标必须来自同一图标家族，保持相同画布、描边宽度、端点风格和视觉重量。
- 图标用于辅助分类识别，始终与分类文字共同出现，不能成为唯一标签。
- 分类活动状态同时改变图标承载面和文字/边框，不能只改变图标颜色。

## 6. Accessibility

### 6.1 目标

以 WCAG 2.2 AA 为明确验收标准。视觉美化不得降低现有语义、键盘、用户偏好或辅助技术支持。

### 6.2 必须满足

- 普通文本对比度至少 4.5:1，大文本至少 3:1；焦点、输入框边界和重要图形至少 3:1。
- 所有操作可由键盘完成，DOM 顺序与视觉顺序一致，不使用正数 `tabindex`，不存在键盘陷阱。
- 所有交互元素具有可见、未被裁切的 `:focus-visible` 状态。
- 保留“跳到主要内容”链接、单一 `h1`、顺序正确的 `h2`、`header/nav/main/aside/footer` 等语义结构。
- 网站 Logo 属于识别内容时提供合适名称；网站图标作为同一链接内的辅助图形时使用空 `alt`，避免重复朗读。
- 图标按钮具有明确的 `aria-label` 和原生 tooltip；搜索框具有可见或程序化标签，清空按钮名称包含动作对象。
- 活动分类使用 `aria-current="true"`；搜索匹配数量通过 `aria-live="polite"` 报告，但连续输入时不得频繁打断。
- 页面在 200% 浏览器缩放和 320px 宽度下无内容丢失、遮挡或页面级水平滚动。
- 触控目标至少 44 × 44 CSS px，目标之间至少 8px。
- 支持 `prefers-reduced-motion`、`prefers-contrast: more` 和 `forced-colors: active`；强制颜色模式下不得隐藏边界、焦点或活动状态。
- 不禁用浏览器缩放，不依赖悬停才能获得信息或操作。

## 7. Implementation Constraints

### 7.1 技术边界

- 保持现有 `config.yaml + Pug + 原生 CSS + 原生 JavaScript + Bun` 架构。
- 不引入 React、Vue、Svelte、Tailwind、CSS-in-JS 或运行时 UI 组件库。
- 网址内容继续由 `config.yaml` 管理，`index.html` 继续由构建脚本生成，不直接手改生成文件。
- 搜索、分类活动状态、主题切换和返回顶部均使用轻量原生 JavaScript。
- Lucide 仅作为构建期图标来源；最终页面不依赖 CDN、图标 API 或运行时图标库。
- 页面继续支持 `file://` 直接打开，不能新增必须通过 HTTP 才能工作的数据请求。

### 7.2 浏览器范围

- 支持 Chrome、Edge、Firefox、Safari 当前稳定版及前两个主版本。
- 同时覆盖目标范围内的 iOS Safari 与 Android Chrome。
- 不支持 Internet Explorer 或已停止维护的旧浏览器。
- 导航、搜索、主题切换和键盘操作必须完整可用；不影响核心任务的现代视觉增强可以渐进降级。

- 仅用键盘完成：跳到主要内容、切换主题、分类跳转、搜索、清空搜索、打开任意网址和返回顶部。
- 在 200% 浏览器缩放和 320px 宽视口检查重排；不得丢失内容、遮挡焦点或出现页面级水平滚动。
- 分别检查 `prefers-reduced-motion: reduce`、`prefers-contrast: more` 与 `forced-colors: active`；状态不能只靠颜色表达。
- 至少人工抽查 VoiceOver + Safari 或 NVDA + Firefox：标题层级、搜索标签、结果 live region、活动分类和“新标签页打开”说明朗读正确。
- 在 Chrome、Edge、Firefox、Safari 的目标版本，以及 iOS Safari、Android Chrome 中完成核心任务抽查。

### 8.6 可用性验收

准备 10 个分布在不同分类的代表性目标网址，分别执行搜索定位和按分类定位。记录从页面可操作到激活正确网址的时间、误点和失败，并按 1.3.1 的阈值判断；不要以开发者熟悉测试步骤后的成绩替代首次任务成绩。另做一次 5 秒第一印象测试，回答必须同时识别“个人网址导航”和“搜索或分类打开网站”这两个要点。

### 9.3 Lucide 本地资产策略

1. 以 4.8 的 17 个 Iconify ID 作为唯一白名单，去掉 `lucide:` 前缀后从 `@iconify-json/lucide@1.2.123` 读取图标数据。

3. SVG 数据只来自锁定的依赖和静态白名单，可以作为可信构建输入插入 Pug；任何 `config.yaml` 字段和用户搜索文本都不得进入未转义 SVG/HTML。
4. 最终 `index.html` 内联所需 UI/分类图标，不请求 Iconify API、CDN 或整套运行时图标库。依赖已按锁文件安装或缓存后，断开网络再次构建仍须成功。
5. 将 Lucide 的 ISC 许可完整保存在 `THIRD_PARTY_LICENSES.md`；升级图标包时先核对名称、视觉变化、许可和 20KB 预算，再单独提交。

### 9.4 搜索数据与过滤算法

初始化时为每个网址条目缓存以下不可变数据：原始标题、原始描述、原始域名、所属分类、原始 DOM 顺序，以及三个可见文本节点的引用。联合索引使用标题、描述、域名和分类，以单个空格连接后执行：

```text
normalize(value) = String(value).normalize("NFKC").trim().toLocaleLowerCase("zh-CN")
terms(query)      = normalize(query).split(/\s+/).filter(Boolean)
matches(item)     = terms.every(term => item.normalizedIndex.includes(term))
```

每次非组合态 `input` 的更新顺序固定如下：

1. 解析关键词；空关键词恢复所有条目与原始文本。
2. 按原始 DOM 顺序计算每个条目的布尔匹配值，不排序、不移动节点。
3. 用原生 `hidden` 同步网址条目与空分类；统计每个分类匹配数及总匹配数。
4. 同步 Workbar、分类导航、分区标题、live region 和 EmptyState；live region 使用完整中文句子。
5. 从缓存的原始字符串重建可见文本。高亮时只在能确认原始字符串边界的片段上创建 `Text` 与 `mark` 节点；无法把 NFKC 命中安全映射回原文时保留匹配但跳过该字段高亮。
6. `disconnect()` 旧 `IntersectionObserver`，在下一帧只观察未隐藏分区；零结果清除 `aria-current`，有结果则建立新的初始活动分类。
7. 仅在空查询变为首个非空查询时滚动目录；同一轮输入不再次滚动。清空后重置这一轮标记，但不主动回顶。

高亮不得使用字符串拼接后赋给 `innerHTML`。推荐把所有命中区间排序并合并后，通过 `DocumentFragment` 依次添加 `Text` 和 `mark`；每次更新先从初始化缓存恢复原文，防止 `<mark>` 嵌套。119 个条目直接同步过滤即可，不使用 debounce、Web Worker 或第三方搜索库。

### 9.5 CSS 实施顺序与约束

1. 先落地 4.10 的浅色 token、深色 token、尺寸与时长，不在组件中重复原始色值。
2. 再实现基础文档流和移动端单列；固定工作栏、分类栏、图标框、按钮和条目尺寸，先消除 CLS 来源。
3. 在 `720px` 增加双列，在 `1024px` 切换单行 Workbar 与 208px 侧栏，在 `1440px` 放宽网格；最多 5 列由网格与最大内容宽共同限制。
4. 最后加入 `hover`、`:active`、`:focus-visible`、`prefers-reduced-motion`、`prefers-contrast` 和 `forced-colors`。交互状态不得改变布局尺寸。
5. 完成后扫描 CSS：除已确认的钴蓝和荧光黄外，中性色不能蓝染；不得残留旧断点、渐变、阴影、模糊、背景图或负 `letter-spacing`。

### 9.6 Scrollspy 与筛选协作

- `observeSections()` 每次都先断开旧 observer，并从 `:not([hidden])` 的分区重新取目标，不能复用筛选前的 NodeList。
- `rootMargin` 必须根据当前实际粘性顶部总高度计算：桌面为 Workbar，窄屏为品牌行、搜索行和 CategoryRail 的总和；不能保留旧的硬编码 `-104px`。视口跨越断点或粘性区域尺寸变化后必须重新计算并重建 observer。
- 筛选更新结束后在 `requestAnimationFrame` 中重建 observer，避免观察筛选前布局。
- 点击分类立即设置候选活动项，随后以 observer 的可见结果校正；活动项变化时根据标签与容器边界计算目标 `scrollLeft`，只对窄屏 CategoryRail 调用 `scrollTo()`，不得用可能带动页面的元素级 `scrollIntoView()`。
- CategoryRail 在初始化、滚动、缩放、筛选和视口变化后更新左右溢出状态，以控制边缘渐隐；该状态只作视觉提示，不改变标签宽度或 Tab 顺序。
- 所有自动滚动都检查 `prefers-reduced-motion`；清空搜索、零结果和主题切换不得留下指向隐藏分类的 `aria-current`。

### 9.7 推荐提交顺序

每个提交都包含对应的重新生成 `index.html`，且通过当时已有的测试：

1. `chore: pin Lucide and UI test tooling`：只增加精确依赖、测试脚本、许可文件与忽略项。
2. `build: provide trusted inline Lucide icons`：扩展构建脚本和图标白名单，保持页面行为不变。
3. `feat: restructure navigation workbar and directory`：修改 Pug 语义与组件结构，保持 11/119 数据守恒。
4. `style: apply responsive technical workbench theme`：一次完成 token、两套主题、三个断点和所有组件状态，避免提交结构与样式长期不匹配。
5. `feat: add local navigation search`：实现过滤、高亮、计数、空状态、快捷键、IME 与 observer 重建。
6. `test: cover navigation UX and accessibility`：补齐搜索样本、视觉截图、axe、键盘与故障状态测试。
7. `docs: record UI verification results`：只记录实际测试结果、截图基线和未解决风险，不改变产品范围。
